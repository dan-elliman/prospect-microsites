PMI's Production Traces Are a Product Roadmap — Here's How to Read Them

PMI is already running agents in production and generating traces in LangSmith. That means there is already a living record of where AI workflows are performing, where they are stalling, and where human reviewers are stepping in to correct outputs. Most teams treat this observability data as a debugging tool. It is actually something more valuable: a signal for what to build next.

What Lives Inside a Production Trace

Every LangSmith trace captures the full execution path of an agent run — the input, each retrieval step, every LLM call, the final output, latency at each node, and any human-in-the-loop intervention. For a regulatory documentation agent working on IQOS submission packages, a trace might reveal that the agent retrieves the correct clinical study data 94% of the time but consistently fails to surface the right aerosol chemistry references when the query comes from a non-English market brief.

That failure pattern is invisible in aggregate metrics. It surfaces in traces.

The Insights Agent as an Internal Analyst

LangSmith's Insights Agent is designed to run over accumulated production traces and answer operational questions in plain language — no SQL, no dashboard configuration required. For PMI's Head of AI or VP of Digital Innovation, that means asking questions like:

  • Which regulatory workflows have the highest human correction rate over the last 90 days?
  • Where are agents timing out on multi-step submission drafting tasks?
  • What document types are most frequently retrieved but least often used in the final output — suggesting retrieval pipeline misalignment?

The answers are not hypothetical — they come from PMI's own operational data, grounded in real submission workflows across real markets.

Turning Observability Into Automation Opportunity

The LangGraph runtime underpinning PMI's longer-horizon agents — multi-step workflows like drafting a market-specific product compliance dossier or synthesizing a scientific literature review for a new reduced-risk product — is built for durable execution with checkpointing. When the Insights Agent surfaces a recurring failure node in one of those workflows, the fix is not a rewrite. It is a targeted adjustment to a specific graph node, testable against the eval dataset before redeployment.

This is the operational loop that separates AI teams running pilots from AI teams running programs: traces inform evals, evals gate deployments, deployments generate new traces. For PMI, where the cost of a regulatory error is measured in market access and not just engineering time, closing that loop with discipline is the difference between AI as an experiment and AI as infrastructure.
