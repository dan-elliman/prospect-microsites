Eval-Driven Agent Deployment: Why FanDuel Can't Afford to Skip This Step

Regulated industries don't get to move fast and fix hallucinations later. If a FanDuel support agent tells a user their withdrawal will clear in 24 hours when the actual hold is 5 business days, that's not a product bug — it's a compliance exposure and a trust-destroying moment that spreads on Reddit within the hour.

This is why the standard "vibe-check the demo and ship it" approach to LLM deployment doesn't work in sports betting. What does work is an eval-driven deployment pipeline — and it's more tractable than it sounds.

The Gap Between Demo and Production

LLM agents perform well on the examples you've seen. They fail on the distribution of inputs you haven't. In a betting context, that distribution is enormous: edge-case promo terms, state-specific withdrawal rules, voided bet scenarios tied to specific officiating calls. No amount of manual testing covers it. You need systematic evaluation against real production traces.

How LangSmith Closes the Loop

LangSmith's eval framework operates in two modes that matter here. Offline evals run your agent against curated datasets — think: 500 real support transcripts with known correct resolutions — before any code ships. Online evals sample live production traces and score them against ground-truth criteria automatically, flagging regressions as they emerge.

The workflow looks roughly like this:

  • Build a golden dataset from historical support tickets, tagged by resolution type and correctness.
  • Define evaluators for the things that matter: did the agent cite the correct promo terms? Did it correctly identify a withdrawal hold reason? Did it avoid quoting payout percentages it can't verify?
  • Run offline evals on every agent change before promotion to staging.
  • Sample production traces continuously, auto-score them, and alert when accuracy on a specific intent category drops below threshold.
# LangSmith eval example
from langsmith import Client
from langsmith.evaluation import evaluate

client = Client()

results = evaluate(
    target=support_agent.invoke,
    data="fanduel-withdrawal-disputes-golden-set",
    evaluators=[resolution_accuracy, policy_citation_check],
    experiment_prefix="withdrawal-agent-v2"
)

The C.H. Robinson Precedent

C.H. Robinson used this exact eval-loop approach to scale an LLM-powered logistics agent from a cautious pilot to 5,500 automated orders per day. The eval infrastructure wasn't a nice-to-have — it was the mechanism that gave the business the confidence to expand scope. FanDuel's path from "pilot bot handling deposit FAQs" to "full-spectrum account management agent" runs through the same gate.

What Confident Looks Like

The goal isn't a perfect agent on day one. It's a measurable agent — one where the engineering team can tell the VP of Compliance exactly what the accuracy rate is on withdrawal policy questions, show the trend line over the last 30 days, and point to the specific traces where it got it wrong and why. That's the artifact that gets an AI agent past legal review and into production at scale.

LangSmith's tracing integrates via OpenTelemetry, so instrumentation doesn't require a rip-and-replace of existing infrastructure. The eval framework sits on top of whatever LLM or agent architecture is already running.
